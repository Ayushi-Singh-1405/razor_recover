Security

Revoco touches real payments. The security model is built on one principle: AI reasons, policy decides, execution is controlled — and every layer is auditable.

Authentication & sessions

Merchants sign in with Google OAuth. The backend exchanges the authorization code server-side and issues an HS256 JWT (merchant id + email, 24-hour expiry) stored in an httpOnly cookie — browser JavaScript cannot read it. Every protected route verifies the cookie server-side via get_current_merchant and returns 401 on a missing, expired, forged, or unknown-merchant session.

  • OAuth code exchange happens server-side; the client secret never reaches the browser
  • Session cookies are SameSite=Lax; tokens are never exposed to JS
  • Secrets live in environment variables only — never in code or the repository

Execution safety

The LLM has zero execution authority. It recommends; a deterministic policy gate decides. The gate cannot be overridden by the model, by tier, or by configuration mistakes:

Webhook authenticity is enforced with HMAC signature verification; webhook events are deduplicated by provider event id; payment links expire after one hour.

Evaluation integrity

The ground-truth outcome fields that grade the agent are generated by a pre-registered policy from a wider signal set than any system sees, are never exposed to the agent or the detector at decision time, and are protected from post-hoc tuning by a versioning rule. The agent earns (or loses) execution authority in rupees recovered — measured, not asserted.

Auditability

Every decision records what the AI thought, what the policy allowed, and why — including decision path and override reason. Every execution action, refusal, escalation, and merchant approval is an immutable audit entry. The public Audit page is a direct view of that trail; nothing in the system acts without leaving one.

Data

The benchmark runs on synthetic data (seeded, reproducible, no real customer records). The live path processes real Razorpay Test Mode transactions only. No secrets are committed to the repository; all credentials are environment variables with placeholder templates.
