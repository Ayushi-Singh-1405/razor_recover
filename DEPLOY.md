# Deploying Repechage on Render (free)

Render's free tier hosts the FastAPI app with HTTPS, and sits in the same
AWS region family as your Neon database — so the dashboard loads fast.
Total cost: **$0** (Render free + Neon free).

The repository contains `render.yaml` (a Render Blueprint) so most of the
setup is automated.

---

## 1. Prerequisites

- Latest code pushed to `github.com/Ayushi-Singh-1405/razor_recover`
- Your Neon `DATABASE_URL` (pooled connection string)
- Google Cloud Console access (for the OAuth redirect URI)

## 2. Deploy via Blueprint

1. Go to https://dashboard.render.com → **New** → **Blueprint**
2. Connect the `razor_recover` repository
3. Render reads `render.yaml` and prepares the service
4. It will prompt for the secrets marked `sync: false`:
   - `DATABASE_URL` — your Neon **pooled** connection string
   - `RAZORPAY_KEY_ID` / `RAZORPAY_KEY_SECRET` / `RAZORPAY_WEBHOOK_SECRET`
   - `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET`
   - `OPENROUTER_API_KEY`
   - `APP_BASE_URL` — `https://repechage.onrender.com` (match your service name)
   - `FRONTEND_URL` — `https://repechage.onrender.com`
5. `JWT_SECRET` is auto-generated by Render — nothing to do
6. Click **Apply** — Render installs dependencies, runs
   `alembic upgrade head`, and starts uvicorn

## 3. Google Cloud Console

1. APIs & Services → Credentials → your OAuth client
2. Add `https://<service-name>.onrender.com/auth/google/callback`
   as an **Authorized redirect URI** (must match `APP_BASE_URL` exactly)
3. If the OAuth consent screen is in **Testing** mode, add your Google
   account as a test user — only test users can sign in until published

## 4. Verify

- `https://<service>.onrender.com/health` → `{"status":"ok"}`
- `/` → Repechage landing page
- `/login` → Google sign-in → dashboard with live data
- The keep-warm thread runs inside the deployed app, so Neon stays awake
  and the dashboard stays fast

## 5. Avoid free-tier cold starts (optional)

Render free services spin down after ~15 minutes without traffic; the next
visitor waits ~50 seconds. To keep the demo warm:

- Create a free UptimeRobot monitor pinging
  `https://<service>.onrender.com/health` every 5 minutes

(Reders' 750 free instance-hours/month covers 24/7 for one service, so the
pinger doesn't exceed the free allowance.)

## 6. Notes

- `alembic upgrade head` runs on every deploy — migrations are never forgotten
- The Neon keep-warm thread (added after the lost-run incident) keeps the
  database compute awake so the dashboard never cold-starts
- `LIVE_EXECUTION_ENABLED` defaults to `false` on the deployment — set it to
  `true` in the Render dashboard only when you want live payment-link
  creation from the dashboard
- Never commit real secret values; Render stores them encrypted
